虽然此题比较简单，但是我一开始没什么思路，随便口胡了一下，然后稍微改改就过了。我非常震惊，决定记录一下思路。

题目是要求建最小生成树，直接想贪心每次取最小边权直到要成环。但是点数为n*m=9e12，普通的建图来做肯定爆。

看到题目给的数都是一行一列的数据，可以想到按行和列来操作而不是一个个点来操作。

那还是贪心的思路，把行和列的值都放到一个数组里，排序，从小到大取，取满n行m列

然后又会发现个问题，会成环，所以每行每列的边不能取满，但取多少呢。一般的思路就是用并查集一个个判断，但我们不是对点操作所以不行。

因此考虑什么时候会成环，考虑当围成了这样时：
![](https://cdn.luogu.com.cn/upload/image_hosting/e0sguudf.png)
(蓝色表示已选的边)

此时若要选1-4行的话就会出现环，假设我们现在要选行2，既然不能全选，就考虑能选几条，比如图中此时行二只能选3条（即1-2，2-3，4-5。但先不用考虑是哪三条）

不难发现，当前这一行能选几条边取决于目前已经选了几列，当选的列数多于两列时，每多一列就少一条。选列时也同理。

其实仔细想想是不用管选那些边的，只用管选了哪些行列，每行每列中具体选哪些不用管。因为只要你选了这一行（列），那么这一行（列）上的所有点都加入到了目前的整颗树中，所以只需要保证他们之间没有边就行。

（感觉还是说得有点抽象，不过这题还算简单，就这样吧）

代码：

```cpp
#include<bits/stdc++.h>
using namespace std;
typedef long long ll;
const int N = 3e6 + 10;
ll n,m,v1;
ll h,l;
struct nd
{
	ll num;
	int hs;
}v[N];
bool cmp(nd x,nd y)
{
	return x.num < y.num;
}
int main()
{
	cin >> n >> m;
	for(int i = 1;i <= n;i++)
	{
		cin >> v[i].num;
		v[i].hs = 1;
	}
	for(int i = 1;i <= m;i++)
	{
		cin >> v[i + n].num;
		v[i + n].hs = 2;
	}
	sort(v + 1,v + n + m + 1,cmp);
	ll ans = 0;
	for(int i = 1;i <= n + m && h + l < n + m;i++)
	{
		if(v[i].hs == 1)
		{
			ans += v[i].num * (m - 1 - (l >= 2 && h >= 1 ? l - 1 : 0));
			h++;
		}
		else
		{
			ans += v[i].num * (n - 1 - (h >= 2 && l >= 1 ? h - 1 : 0));
			l++;
		}
	}
	cout << ans;
	return 0;
}
```
